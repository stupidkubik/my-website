# Ревью проекта и план доработки

**Дата:** 4 марта 2026  
**Проект:** Evgenii Rubin — Frontend Portfolio (Next.js 16, Pages Router, React 19, Tailwind)

---

## 1. Резюме

Сайт-портфолио в стиле Systematic Minimalist реализован последовательно: есть главная, About, Projects (список + кейсы по slug), Resume, Contact, 404, sitemap.xml и robots.txt. Стек соответствует AGENTS.md (Next.js, TypeScript, Tailwind, Geist). Сборка и линт проходят. Ниже — сильные стороны, слабые места и приоритизированный план доработки.

---

## 2. Сильные стороны

- **Архитектура и консистентность:** Единый Layout с skip-link, Header с `next/link` и `aria-current`, Footer. UI-примитивы (Section, Stack, Grid, Button, TextLink, ProjectCard, Badge, BulletList, PageTitle) используются последовательно.
- **Навигация:** Внутренние ссылки уже переведены на `next/link` в Header, ButtonLink, ProjectCard и TextLink — пункт P1 из PLAN.md по замене `<a>` на Link по сути выполнен.
- **Доступность:** Skip to content, видимые focus-visible, семантика (main, nav, section, aria-label), поддержка `prefers-reduced-motion` для анимаций.
- **SEO:** SeoHead с title, description, canonical, og:* и twitter:*, sitemap.xml и robots.txt с корректным baseUrl (env + fallback на host).
- **Тема:** Светлая/тёмная тема с инициализацией в _document и сохранением в localStorage, без мелькания.
- **Шрифты:** Geist подключается в _app через `GeistSans.variable` и `GeistMono.variable`, Tailwind использует `var(--font-geist-sans)` — переменные задаются пакетом `geist`, поведение должно быть корректным (при необходимости — проверить в проде).
- **Контент:** Реальный текст из резюме и кейсов, без плейсхолдеров.
- **Проекты:** SSG для `/projects/[slug]`, next/image на странице кейса, медиа в public.

## 3. Слабые места

### 3.1 Критичные / контент и ресурсы

| Проблема | Где | Описание |
|----------|-----|----------|
| **Нет favicon и PWA-иконок** | `_app.tsx`, `site.webmanifest` | В Head указаны `/favicon.ico`, `/apple-touch-icon.png`; в manifest — `/icon-192.png`, `/icon-512.png`. В `public/` этих файлов нет → 404 при загрузке, слабый PWA. |
| **Дублирование данных проектов** | `index.tsx`, `projects/index.tsx`, `projects/[slug].tsx` | Список проектов и тексты кейсов заданы в трёх местах. Расхождения (например, summary в home vs projects vs detail) уже есть. Усложняет поддержку и добавление новых проектов. |

### 3.2 Важные / качество и согласованность

| Проблема | Где | Описание |
|----------|-----|----------|
| **Резюме: PDF через SPA-навигацию** | `resume.tsx` | Кнопка «Download PDF» ведёт на `/media/resume/evgenii-rubin-cv.pdf` через ButtonLink (next/link). Для скачивания файла предпочтительнее явная ссылка `<a href="..." download>` или как минимум убедиться, что при переходе по внутреннему пути файл реально отдаётся и скачивается. |
| **OG-изображения без размеров** | `SeoHead.tsx` | Нет `og:image:width` и `og:image:height`. Соцсети и мессенджеры лучше обрабатывают превью при указании размеров. |
| **Расхождение AGENTS.md и кода** | AGENTS.md | Указан «MDX for pages/case studies» — в проекте MDX не подключён, кейсы в TSX. Либо добавить MDX под контент кейсов, либо обновить AGENTS.md. |
| **Canonical для 404** | `404.tsx` | Передаётся `path="/404"`. Страницы ошибок обычно не индексируют; лучше не выставлять canonical для 404 или явно noindex (noindex уже есть). |

### 3.3 Средний приоритет / полировка

| Проблема | Где | Описание |
|----------|-----|----------|
| **Шрифты (P1 в PLAN)** | tailwind, _app | В PLAN.md отмечено «Fix font variable scope for Geist». В _app переменные вешаются на обёртку, body в globals.css использует `font-sans` — цепочка должна работать. Стоит один раз проверить в проде/разных браузерах; при необходимости задать переменные на `html` в _document. |
| **Линт (P1 в PLAN)** | eslint | В PLAN — «Restore working lint quality gate». Сейчас `npm run lint` завершается успешно; скрипт использует `--ext .ts,.tsx`, а конфиг — flat ESLint 9. Имеет смысл убедиться, что все целевые папки попадают под линт (например, не исключены ли `src` или какие-то файлы). |
| **Sitemap/robots: дублирование slug-списка** | `sitemap.xml.ts` | `projectSlugs` захардкожен отдельно от `projectData` в `[slug].tsx`. При добавлении проекта легко забыть обновить sitemap. |

### 3.4 Низкий приоритет

| Проблема | Где | Описание |
|----------|-----|----------|
| **Theme в manifest** | `site.webmanifest` | `theme_color` и `background_color` только светлые. Для PWA в тёмной теме можно задать тёмные значения или оставить как есть до появления полноценного PWA-сценария. |
| **Единый источник проектов** | Разные страницы | Вынесение в общий модуль (JSON/TS) с типизацией и использованием в home, projects, [slug] и sitemap — см. P3 в PLAN. |

## 4. План доработки

### Фаза 1 — Быстрые исправления (1–2 часа)

1. **Иконки и manifest**
   - Добавить в `public/`: `favicon.ico`, `apple-touch-icon.png`, `icon-192.png`, `icon-512.png` (хотя бы минимальные заглушки или сгенерированные из одного источника).
   - При необходимости обновить `site.webmanifest` (пути, имена).

2. **Скачивание PDF резюме**
   - Заменить кнопку «Download PDF» на `<a href="/media/resume/evgenii-rubin-cv.pdf" download>...</a>` или оставить ButtonLink, но проверить, что по ссылке отдаётся PDF и браузер предлагает скачать (не SPA-переход).

3. **404 и SEO**
   - Для страницы 404 не передавать `path` в SeoHead (чтобы не выставлять canonical на /404) или явно документировать решение. Noindex уже стоит — достаточно.

### Фаза 2 — Единый источник проектов и SEO (2–4 часа)

4. **Один источник данных проектов**
   - Вынести данные в общий модуль, например `src/data/projects.ts` (или JSON + типы).
   - Типы: slug, title, summary, контент для кейса, ссылки, медиа, ogImage.
   - Использовать этот источник в: главная (selected projects), `/projects` (список), `/projects/[slug]` (getStaticPaths + getStaticProps), `sitemap.xml.ts` (список slug’ов).
   - Убрать дублирование summary/названий между страницами.

5. **OG-изображения**
   - В SeoHead при наличии `ogImage` добавлять опциональные `og:image:width` и `og:image:height` (например, из данных проекта или общие 1200×630).

6. **Проверка шрифтов**
   - В проде/разных браузерах убедиться, что Geist применяется. При необходимости задать CSS-переменные шрифтов на `html` в _document и оставить в _app только классы.

### Фаза 3 — Документация и полировка (около 1 часа)

7. **AGENTS.md**
   - Привести в соответствие с фактом: либо «Content: TS/JSON for projects and resume; MDX optional later», либо описать шаги по внедрению MDX для кейсов.

8. **PLAN.md**
   - Отметить выполненные пункты Review Remediation Plan (P1 next/link — сделано; P1 lint — проверить и при успехе отметить; P1 шрифты — после проверки).
   - Перенести оставшиеся пункты в актуальный бэклог с приоритетами из этого плана.

9. **Чек-лист перед деплоем**
   - LCP: главная и кейсы используют лимитированные размеры изображений и priority где нужно.
   - Переходы между страницами без полной перезагрузки (уже так при использовании next/link).
   - Доступность: быстрая проверка фокуса, skip-link, aria-current.
   - SEO: проверить один раз выдачу в соцсетях (og:image, заголовки).

### Фаза 4 — По желанию

10. **MDX для кейсов** (если нужна редакция контента без правки TSX): подключить @next/mdx, вынести текст кейсов в MDX, оставить данные (мета, ссылки, медиа) в общем источнике.
11. **PWA**: полноценный service worker и кэширование — только если планируется установка сайта как приложения.
