## Находки

### 1. CI не проверял часть коммитов на `main` — исправлено

`concurrency` в `quality.yml` отменял текущий прогон при каждом новом пуше, в том числе на `main`. Прогоны для мержей #26 (`ed221e0`) и #27 (`00e8648`) завершились как `cancelled`, и эти коммиты целиком не проверены. Теперь отменяются только устаревшие прогоны PR (`cancel-in-progress: ${{ github.event_name == 'pull_request' }}`), а каждый коммит на `main` проверяется полностью.

### 2. Устаревшая документация — исправлено

README указывал ESLint 9 (с #25 используется ESLint 10). В `PLAN.md` пункты ремедиации оставались неотмеченными, хотя всё смержено, а #24 закрыт: его коммит вошёл в #25.

### 3. Переключатель темы: доступное имя не содержит видимую подпись — открыто

`ThemeToggle` показывает текст «Light»/«Dark», а доступное имя — «Switch to dark theme». Это нарушает WCAG 2.5.3 Label in Name (уровень A): пользователь голосового управления, сказав «click Light», не найдёт кнопку. Вдобавок `aria-pressed` сочетается с меняющимся `aria-label`, и скринридер читает «Switch to light theme, pressed», что противоречиво. Lighthouse это не ловит: аудит `label-content-name-mismatch` экспериментальный и по умолчанию выключен. Вариант исправления: стабильное имя, содержащее видимый текст (например, видимое «Dark» + `aria-pressed`, без `aria-label`). Это меняет видимый UI и селекторы e2e, поэтому нужно решение по дизайну.

### 4. LCP 2.0–2.3 s на mobile — открыто

Единственный аудит ниже 100% на всех страницах. LCP-элемент — текст в шапке («Evgenii Rubin / Open to Work»); около 0.5 s занимает задержка отрисовки. Оба шрифта Geist (Sans и Mono, ~70 kB каждый, вместе 141 kB из 295–340 kB страницы) грузятся через preload с высоким приоритетом на каждой странице, хотя Mono нужен только для технических деталей. Пакет `geist` не даёт отключить preload, поэтому для Mono понадобится `next/font/local` с `preload: false`. Ожидаемый эффект небольшой (Performance уже 98–99), но это самый дешёвый резерв.

### 5. Смерженные ветки остаются на GitHub — открыто

`delete_branch_on_merge` выключен, и на remote лежат ветки всех смерженных PR (`build/*`, `chore/*`, `ci/*`, `docs/*`, `fix/*`, `test/*`, `dependabot/*`, `codex/*`). Рекомендация: включить Settings → General → «Automatically delete head branches» и удалить смерженные ветки.

## Метрики: как устроено

- `.github/workflows/metrics.yml` запускается после каждого успешного Production-деплоя Vercel (`deployment_status`), по понедельникам и вручную.
- Lighthouse проходит каждую страницу из прод-`sitemap.xml` 3 раза; страницу представляет медианный прогон, а бейдж показывает самую слабую страницу. Новые страницы попадают в замер автоматически.
- MDN HTTP Observatory оценивает заголовки.
- `scripts/collect-metrics.mjs` (тесты: `npm run test:metrics`) превращает результаты в shields.io endpoint JSON, `metrics.json` и отчёт по страницам.
- Результат публикуется в ветку `metrics` одним коммитом через force-push, так что ветка не растёт. В ветке лежит `vercel.json` с `deploymentEnabled: false`, чтобы Vercel её не деплоил. Если любой замер падает, публикации нет и бейджи сохраняют последние валидные значения.
- HTML-отчёты Lighthouse хранятся 14 дней как артефакт `lighthouse-reports`.

## Решения и ограничения

- **Нет бейджа покрытия тестами.** У React-компонентов нет юнит-тестов, а процент покрытия одних build-скриптов вводил бы в заблуждение. Если нужен, реалистичный путь — покрытие e2e через V8 coverage в Playwright с source maps.
- **Замеряется прод, а не превью PR.** Превью и уникальные URL деплоев закрыты Vercel Authentication (302 на SSO).
- **Lighthouse запускается через `npx` с зафиксированной версией** и не попадает в `package.json`, чтобы не расширять `npm audit` и `npm ci` остальных job. Цена — версию обновляет человек в `metrics.yml`, Dependabot её не видит.
- **Пропущенные прогоны в Actions.** `deployment_status` срабатывает и на превью-деплои; такие прогоны отмечаются как skipped.
- **Первый запуск.** До первого прогона после мержа ветки `metrics` нет, и бейджи метрик показывают «resource not found». Мерж в `main` запускает Production-деплой, а он — первый замер.
